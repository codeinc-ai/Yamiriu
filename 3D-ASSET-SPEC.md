# Outfit builder 3D asset spec (avatars + garments)

The `/outfit-builder` page (PRD 2.6, 4.4, WF-004) loads a base avatar `.glb`
per avatar type, then attaches a garment `.glb` on top when a product is
selected. This doc is the contract the founders' 3D artist must follow so
real assets drop in without any code changes.

## Current state

`public/models/avatars/{men,women,kids}.glb` are **placeholder mannequins**
— simple capsule/sphere primitives generated by
[`scripts/generate-placeholder-avatars.mjs`](scripts/generate-placeholder-avatars.mjs)
(run with `node scripts/generate-placeholder-avatars.mjs` to regenerate).
They exist so the loading pipeline (fetch → parse → render → orbit →
shadow) is real and testable today, not just a code stub. Replace them with
real sculpted/rigged models per the spec below whenever they're ready — no
other code needs to change as long as the contract is followed.

Garment `.glb` files referenced by `products.modelUrl` in the seed data
(`db/seed-data.ts`, e.g. `/models/men/milano-linen-shirt.glb`) **do not exist
yet** — this is expected. The builder's per-item loader already handles a
missing/failed garment file gracefully (flat 2D image fallback + retry, see
`components/outfit-builder/`), so the page is fully usable today; garments
just won't render in 3D until real files are dropped at those paths.

## Avatar contract (`public/models/avatars/{men,women,kids}.glb`)

- **Format**: glTF 2.0 binary (`.glb`), single file, no external `.bin`/texture
  references (embed everything).
- **Compression**: mesh geometry should use `KHR_draco_mesh_compression`
  where the DCC tool supports exporting it (Blender's glTF exporter has a
  Draco checkbox). Not required for small/simple meshes — use judgment
  based on final triangle count. The loader
  (`components/outfit-builder/gltf-loader.ts`) is already wired with
  `DRACOLoader` (decoder files at `public/draco/`) and `MeshoptDecoder`, so
  either compression scheme (or none) works without code changes.
- **Units / scale**: meters, real-world human scale (e.g. an adult men's
  avatar ≈ 1.75–1.85 m tall from origin to the top of the head).
- **Origin**: at the avatar's feet, centered on the X/Z ground plane (i.e.
  `(0, 0, 0)` is between the feet, not the pelvis or the bounding-box
  center). The camera/lighting rig in `components/outfit-builder/` assumes
  this — an avatar authored with a different origin will appear to float or
  sink into the floor.
- **Orientation**: model faces `+Z`, up axis `+Y` (glTF's standard
  convention — most DCC export presets default to this already).
- **Root node name**: `Avatar` (any child mesh/bone names below it are
  fine) — this is only used for a sanity check when loading, not
  hard-required, but keeping it consistent avoids confusion when debugging.
- **Materials**: PBR (`MeshStandardMaterial`-compatible — i.e. standard
  glTF PBR metallic-roughness), no baked lighting. The scene provides
  neutral studio lighting; avatars/garments should not have their own
  baked highlights/shadows.
- **Pose**: a neutral **T-pose or A-pose**, matching whatever pose the
  garments for that avatar type are rigged/authored against (see below) —
  the two must match, since garments are simply parented to the avatar at
  identity transform with no runtime re-posing.

## Garment contract (`products.modelUrl`, one `.glb` per product)

Garments are **not animated or re-posed at runtime** — the builder attaches
each garment as a direct child of the avatar's root object, in its own
authored transform. This means the whole visual alignment burden is on the
artist authoring the garment against the **exact same reference
avatar mesh, scale, origin, and pose** used for that avatar type's base
model above (same 1.75–1.85 m men / proportionally scaled women / kids
scale, same feet-at-origin convention, same pose).

- **Format**: glTF 2.0 binary (`.glb`), same compression notes as above.
- **Scale/origin/orientation**: identical convention to the avatar it's
  designed for (see above) — a garment authored to a different scale or
  origin will clip through or float off the avatar, since nothing at
  runtime rescales or repositions it.
- **Rigging**: garments **may** include a skinned mesh + skeleton (e.g. if
  the artist wants it to deform naturally around the avatar's body shape in
  its bind pose) or may be a simple static mesh — both work identically at
  runtime, since we only ever render the garment's own authored bind pose
  (no bone manipulation happens in code). If a skeleton is included, name
  its bones to mirror the avatar's own bone names for future-proofing
  (in case animated try-on is added later), but this isn't required today.
- **One product = one file**: each `products.modelUrl` points at a single
  self-contained `.glb` (no shared external assets across garments).
- **Category → avatar type**: a garment's `category` (men/women/kids)
  **must** match the avatar type it was authored against — the builder
  never mixes a men's garment onto a women's/kids' avatar.
- **File size**: keep individual garment files small (aim under ~2 MB after
  compression) — they're fetched on demand every time a shopper selects
  that item, not bundled with the page.

## Where this is enforced in code

- Loader setup (DRACOLoader/MeshoptDecoder wiring): `components/outfit-builder/gltf-loader.ts`
- Avatar loading + attachment point: `components/outfit-builder/avatar-scene.tsx`
- Garment load/replace/deselect/error-fallback: `components/outfit-builder/avatar-scene.tsx`
- Placeholder avatar generator (for reference on how the placeholders were
  built, and to regenerate them if needed): `scripts/generate-placeholder-avatars.mjs`
